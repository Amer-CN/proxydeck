## 二、根因聚类（按代价排序）

- **comate 2026-11-15 六连击**：`3194c48` 短名/异常 server_name → `99a7f70` 坏参数透传 →
  `b3d018c` 保证合法 JSON → `53dfba3` 提示词加固 → `7dc2fe9` 缺名字不丢整批 →
  `3685bce` 502 重试。每版只堵当天看到的那一帧。
- **codebuddy 11128 四轮**：`0415ec1`（10-17 换号冷却）→ `847d335`（10-25 11140 分流）→
  `2ee165c`（11-05 对齐官方客户端与错误治理）→ `00511d5`（11-21 改写身份句自愈）。
  最终定案的关键事实是：**所有** 11128 的 `displayTips` 都写 "channel verification"，
  拿它分流等于把全部 11128 当通道校验（旧实现如此，改写与按号治理全成死代码）。
- **codearts 2026-10-26 六连击**：keyMap 漏 `ca` → 甲板挪位 → 鼓轮副页 → 设置槽 →
  复制绑定 → 空 role 规整。每一条都是"界面/协议的一个角落"。
- 共性：**修复以「一帧」为单位，不以「一族」为单位**。样本没有沉淀，下一个人/下一版本
  会再撞同族的另一帧。

### R2 发版粒度 = 修复粒度，放大一切手抄风险

单 fix 一版意味着每修一个点就要：改 12 处版本锚点 → 补 CHANGELOG → 构建 → 打 tag →
发 Release（附 exe）。6 个单 fix 版本 = 6 遍这套动作。发版动作越频繁，
"漏改一处版本串"的概率线性上升——v3.10.0 的 `UI_CUR` 漏改、2026-10-18 的
`CHANGELOG_DATA` 全局替换事故，都是在这条流水线上产生的。攒版裁决的本意就是
把 N 次动作压成 1 次。

### R3 多副本手工同步，且其中一半没有机器校验

版本号在 12 处手抄；UI 三副本；CHANGELOG 两副本（md + ui.html 内的 CHANGELOG_DATA）。
其中「UI 三副本」「CHANGELOG 版本号唯一/降序/同集合」已有门禁，
**「12 处版本串互相一致」「CHANGELOG 顶条 = CLAUDE.md 当前状态 = 最新 tag」没有**。
2026-11-24 复盘当场就撞上：`APP_VERSION`/tag/README/version.rc 都是 v4.10.2，
CLAUDE.md 写着 v4.10.0。当天会话据此把外置 exe 版本判错了一次。

### R4 门禁可空转：全绿 ≠ 测过

SKIP 分支依赖本机安装（Qoder、Tuanjie）、DPAPI 夹具、可见窗口。换一台机器跑，
`golden_qoder` 的大部分组直接不打。项目已有「SKIP 要打印并计数」的写法，
但没有**汇总可见性**，也没有「扫描集合为空就红」的硬约束。本轮补了可复算的
SKIP 清单（`tools/retro-metrics.ps1` 末段），没有造棘轮（理由见第五节）。

### R5 交接文档抄「现状」，必然过期

`CLAUDE.md` 的「服务现状」曾写死 PID 36496 / exe v4.9.10 / 8785 未启动。

## 五、没做的（以及为什么先不做）

1. **发版节奏没有自动门禁。** 单 fix 一版是真问题（数据在第一节），但 tag 是人对外的
   动作，脚本无法判断"这一版该不该发"；硬加"同日第二个 tag 就红"会误伤用户主动发版。
   本轮只量化 + 重申攒版裁决。可做的小改进（未做）：发版脚本在"距上次 tag < 2h 且本次
   只有 fix"时打印确认提示，而不是报错。
2. **样本库没有强制门禁。** 规则 25 靠评审。技术上可以给 comate/codebuddy 各加
   「`tests/fixtures/` 存在且非空、最近一次分类器改动必须伴随夹具变更」的检查，
   但两个 crate 的夹具组织形态不同，本轮先把规则立住，避免造一个扫不到点上的检查。
3. **SKIP 棘轮没做。** SKIP 数量随机器（装了什么）变化，基线不稳定；硬基线要么天天红、
   要么被人调高（等于删检查）。当前只提供计数与清单，要求新 SKIP 在评审里说明。
4. **UI 三副本结构没动。** 单文件 1.5MB + 逐字节内嵌是既有合同（build.rs 锁着），
   拆分会牵动窗口/桥/发版，收益不抵风险；本轮的"机械返工"只能承认存在。
5. **窗口外不追。** 2026-09 及更早的 codebuddy 13 个 fix 只作为 R1 的旁证，未逐条复盘；
   本轮数据边界 = `2026-10-18`。
6. **没有新建 Skill。** 用户级 `bug-retro` 已经覆盖方法；本项目真正的缺口是"发版同步"
   和"取数"，用一道测试 + 两个脚本解决比再写一份 skill 更便宜。

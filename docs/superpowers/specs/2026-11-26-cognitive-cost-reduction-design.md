# ProxyDeck 降低接手成本：设计与范围

日期：2026-11-26。审查基准：`0daefd9`。本文件是交给新执行窗口的设计输入；实施步骤见[执行计划](../plans/2026-11-26-cognitive-cost-reduction.md)。用户把配套提示词发给执行窗口，即授权在以下范围内实施，不需要重新做一轮方向讨论。

## 目的与完成后的样子

让一位熟悉 Rust、异步 HTTP 和桌面应用、但没有项目背景的工程师，能从一个入口追踪关键行为；修改账号策略、区域切换或响应处理时，不必先读迁移历史，也不必记住散落的人工配对操作。

本次不追求行数、文件数或抽象层数的指标。结果应体现为：每个重要事实有明确所有者；名字准确描述行为；请求执行、账号策略和响应交付之间的边界可测试；现有客户端和用户配置继续可用。

## 当前事实和证据等级

- 工作区有 10 个 Rust crate；宿主依赖各后端，后端之间没有复杂的工作区依赖网。见[工作区定义](../../../Cargo.toml)和[宿主依赖](../../../rs-gui/Cargo.toml)。
- 审查时统计到 `src` 下 176 个 Rust 文件、85,681 行（含内联测试和辅助代码）；`tests` 下 Rust 代码 24,967 行；[UI 唯一源](../../../app/ui.html)共 11,421 行。这些是路径统计，不是纯业务代码量。
- 前一轮做了静态阅读和两路交叉审查，没有执行测试、请求真实上游或启停服务。本文的竞态和异常链均是待组合测试确认的线索，不能引用成线上复现结论。
- 2026-11-26 编写本方案时已重新核对 HEAD、工作树和 Cargo 测试目标；HEAD 仍为 `0daefd9`，写方案前工作树干净。未宣称任何测试通过。

## 采用的路线

比较过三条路径：

1. 只改名称和注释：风险低，但区域状态、账号续期、响应提交等非局部依赖继续存在。
2. 分模块渐进调整：先建立有意义的行为测试，再收拢状态所有者，最后合并已证明一致的基础逻辑。每步可以独立提交和评审。
3. 重写 UI 或建立通用代理框架：改动范围大，容易把必要的平台差异藏进配置、回调和适配器，增加新的理解负担。

采用第 2 条。一个执行窗口串行实施，可以请只读审查者核验；本任务不拆成多个并行写入窗口。

## 默认技术决定

以下是本方案的实施默认值，不冒充用户逐项指定的结构；执行者可在不扩大范围、不改变合同的前提下调整内部文件名，并在进度记录中解释。

- 沿用 Rust、WebView2、内嵌 HTML 和现有依赖；不换前端框架，不引入包管理体系。
- UI 继续以原件为唯一源、保留嵌入副本和哈希门禁。先把同步自动化，不在本轮改成新的 UI 打包体系。
- 宿主 bridge 的函数名、位置参数、JSON 字符串返回和现有字节合同保留；在内部增加明确的 API 入口和结果类型。
- 各平台保留自己的请求策略；不创建通用 Provider、动态插件 SDK 或通用重试 DSL。
- 优先按职责拆分实际改动的模块；不为文件大小而移动全仓代码。
- 账号稳定 ID 与轮换凭据分离；兼容旧配置，不能简单用会轮换的 AK 或可编辑显示名充当永久身份。稳定 ID 和旧身份别名从仍有记录的账号开始持久化。升级前已删除、仅剩旧 identity 的无 domainId 记录，只保留原字符串的精确匹配；资料不足时不猜测跨 AK 轮换归属，不按同名合并。
- 配置兼容保证当前已解析的已知字段及新增 ID/别名元数据的读写往返；当前实现并未保留未知字段，本轮不额外承诺未知字段往返。
- 同一数据目录允许多插件实例；续期用进程内按账号协调加跨进程互斥，取得锁后重新加载最新凭据，保存时合并其他账号更新。锁只作用于项目自己的数据，不改系统权限；测试使用临时目录和假 STS。
- COMMAND 输出流持有独立的 `Arc<Mutex<UsageStats>>` 统计句柄和自有请求元数据，不借用已返回函数内的 `&Proxy`；EOF、取消和读错的记账边界在 T11 明确。
- 纯重构保持外部行为。本文列明的行为缺陷只在新增组合测试证明后修复；另行发现的问题记录证据，避免顺手扩张。
- 版本多处锚点本轮保持现有版本；生成和检查工具可消除重复手工操作，不借本轮升版或重写历史日志。

## 不可破坏的边界

1. 完整阅读[项目纪律](../../../CLAUDE.md)。不得发版、推送、打 tag、覆盖或改名运行中的成品 exe、重启 GUI/后端、执行真实更新换血。不得操作真实账号数据、系统权限或 DSH 插件/profile。
2. 既有生产端口只读观察；测试使用随机回环端口和临时数据目录。假 worker/假 STS/假上游与合成账号可以使用；禁止真实登录、真实额度请求和真实账号续期。
3. 团结签名、会话、UA、凭据换取和请求字节顺序属于特别保护区。生命周期重构不能顺便更改其语义。见[团结红线](../../../CLAUDE.md#-红线团结凭证链2026-08-27-官方客服实证)。
4. 健康外部后端接管复用、不重启；停止仍治理注册端口；关 GUI 不结束独立插件；切换区域不隐式停止另一地区。
5. 更新标记与无标记是两种计划来源。保持空闲插件关闭、核心 55990 不参与插件换血、未知镜像在无标记路径不动等既有规则。
6. 不修改冻结的 `tests/golden/**`、已登记比较豁免或历史变更日志来迎合新实现。不能删测试、降断言、增加跳过或把被测策略 mock 掉。允许增加行为断言；源码结构调整所需的测试适配必须保持原断言强度并单独说明。
7. 共享 Cargo target 沿用本机既有配置；若工作树没有该配置，使用项目约定的共享目录 `E:\cargo-target\workspace`。不另建逐 crate 缓存、不清缓存。

## 目标职责

- UI：`PTApp` 负责机械交互；业务状态提供区域与页面上下文；`hostApi` 负责宿主调用、JSON 解码和错误归一。展示 DOM 只消费状态。
- 宿主：插件定义描述身份和端口；生命周期状态描述本进程创建或外部接管；健康快照描述当前观察；旧 bridge DTO 只在出口组装。
- 平台执行：请求准备 → 账号/凭据获取 → 单次上游尝试 → 提交前校验 → 策略决策 → 响应交付。每个平台可以有自己的步骤，不强制共享算法。
- 码道账号：一个管理边界负责账号解析、旧身份别名、凭据版本、续期协调和运行态恢复；各 HTTP handler 不直接拼接这套规则。
- 流式响应：正文开始交付后不再换号重放；提交前允许现有策略内的重试；测试可以把真实流收集为字节，再继续黄金比较。

## 如何证明有改善

核心验收使用执行计划的 12 个行为场景，均运行实际业务路径，只替换外部上游/进程和临时数据，不替换被测状态机。测试要能在原缺陷或对应突变上变红，修改后变绿。

结构验收由只读审查者追踪五条路径：区域切换、插件接管、账号续期、业务错误恢复、COMMAND 首帧交付。对每条指出权威状态、提交点和清理者，列出实际跳转；不能靠新增 README 宣称已经解耦。

旧有测试按任务运行，结尾再做工作区级检查，覆盖 feature 并集。基线已存在的失败/跳过须逐项保留说明；新增和被整改的业务场景不能被跳过。测试统计应按目标/用例对应，不以一处总数增长掩盖另一处删除。

- 真实数据迁移、真实续期、安装运行中的新版本。
- 重写版本历史或把发布工具改造扩展为完整发布流水线。
